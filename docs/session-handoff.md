Проверить assignee и claims, создать отдельную `feat/<issue>-<slug>` от свежего
`origin/dev`; уже начатые `codex/<issue>-*` остаются допустимыми. Все изменения,
включая документацию, сначала в feature. Только merge `--no-ff` через `danil`
в `dev`, без squash/rebase/force и без переключения чужих общих worktree.
Deployment ручной. Текущий приоритет — сборка и реальные сценарии агентом,
без написания и запуска репозиторных тестовых наборов.

## Что проверять на dev Данила

Адрес: https://dev-danil.saint-tibo.win, SSH alias `saint-dev-danil`.
Быстрый вход и dev-креды — [browser-testing.md](browser-testing.md).

1. Readiness, точный `/opt/saint-tibo/current`, состояние backend/frontend/
   postgres/processing-worker; не выводить `.env` или токены.
2. Настоящий вход → `GET /api/v1/me` → совещание и запись → raw upload
   исходника → готовое каноническое WAV → приватный media Range.
3. `POST /jobs` с уникальным `request_key`, `language=ru`,
   `target_stage=transcribe`; повтор с тем же ключом возвращает ту же задачу.
4. Polling до terminal status, затем версия результата и реплики с целыми
   таймкодами в границах записи. Не логировать текст транскрипта.
5. Чужой пользователь не видит запись/задачу/результат; logout отзывает
   сессию. Удалять только созданные проверкой данные и временные аккаунты.

Структуры и команды: [processing-jobs.md](processing-jobs.md),
[transcription.md](transcription.md), [media-proxy.md](media-proxy.md).
Два исходных MP3 кейса в `input-audio/` добавлены по явному поручению владельца;
пользовательские записи, транскрипты, модели и серверные секреты в Git не вносятся.

Модель small INT8 работает отдельным процессом/окружением. Worker имеет
только внутреннюю Docker-сеть к PostgreSQL, read-only аудио и модели;
обработка не использует внешний STT API. На dev Данила модель подготовлена
в `/opt/saint-tibo/models/small`; новые серверы готовятся по transcription.md.

## Перед удалением worktree или архивацией задачи

Сверить уникальные коммиты, tracked/untracked/ignored файлы и владельца.
Незавершённые исходники, приватные `.env` и локальные материалы сохранять.
Архив задачи сохраняет историю; удаление worktree не является обязательным
условием начала новой чистой задачи. Детальный снимок завершённой проверки
и остаток работ всегда читать в #94.
