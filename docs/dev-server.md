# Серверы и ручные запуски

CI/CD и автоматического развёртывания нет. Каждый участник проверяет
свою работу на личном dev-сервере; production обновляет Данил из `main`.

| Окружение | SSH alias | URL |
| --- | --- | --- |
| Production | `saint-prod` | https://saint-tibo.win |
| Данил | `saint-dev-danil` | https://dev-danil.saint-tibo.win |
| Иван | `saint-dev-ivan` | https://dev-ivan.saint-tibo.win |
| Артём | `saint-dev-artem` | https://dev-artem.saint-tibo.win |

Окружения независимы: своя база, пароли, сессии и TLS-сертификаты.
Сессия с одного окружения не даёт доступа к другому.

## Подготовка

Локально нужны Git и SSH. SSH-доступ настраивается отдельно. Серверу нужны
Docker Engine/Compose, Python 3 и curl; SSH-пользователю — доступ к Docker
и `/opt/saint-tibo`. GitHub-токен на сервере не нужен.
DNS домена должен указывать на нужный сервер, порты 80/443 — быть доступны.
Caddy получает и продлевает сертификат, перенаправляет HTTP на HTTPS.

Только gateway публикуется наружу. PostgreSQL, API и frontend слушают
loopback хоста, а между собой общаются в Docker-сети. API доступен через
тот же HTTPS origin: `/api/v1/*`, `/health/*`, `/docs`; `/api/auth/*`
обслуживает Better Auth в frontend. Caddy сохраняет исходные пути.

## Dev

Из чистой рабочей копии с закоммиченными изменениями:

```sh
sh scripts/dev-deploy.sh saint-dev-danil
```

Каждый использует свой alias. Команда отправляет tracked-файлы текущего
коммита, собирает образы, выполняет миграции, ждёт health и проверяет HTTPS.
После интеграции в `dev` взять свежий `dev` и вручную повторить запуск.
Push ничего не развёртывает.

## Production

Только после проверки на dev-сервере и слияния в `main`:

```sh
git switch main
git pull --ff-only origin main
sh scripts/deploy.sh saint-prod
```

Скрипт требует точное совпадение локального `main` с `origin/main`.
Он не сливает ветки и не делает push.

## Окружение и данные

Секреты генерируются на сервере при первом запуске и остаются
в `/opt/saint-tibo/.env` с правами `600`. Повторный запуск сохраняет их
и данные. При первом переходе с localhost скрипт согласует HTTPS origin
для auth, API и frontend. Дальнейшие настройки `.env` сохраняются.

Версии находятся в `releases/<sha>`, `current` указывает на последний
успешный запуск. Образы и сертификаты повторно используются.
Контейнеры автоматически восстанавливаются после перезапуска Docker;
автоматического обновления кода нет. Старые releases не удаляются скриптом.

Изменение `VITE_API_URL` требует пересборки frontend. Не запускайте
локальный `seed` на публичных серверах. Демо-пользователи не создаются
при deployment; рабочие аккаунты создаются через регистрацию.
Не выполняйте `docker compose down -v`: это удаляет постоянные данные.

## Проверка

- Вход, регистрация, выход; обычный пользователь не получает admin-доступ.
- Изменённый сценарий целиком в RU/KK/EN, включая ошибку и пустой результат.
- `/health/ready`, консоль браузера и логи:

```sh
ssh saint-dev-danil 'cd /opt/saint-tibo/current && docker compose logs --tail=60 backend frontend gateway'
```

В issue указать проверенный SHA, URL и результат. Production и коллеги
не меняются при запуске команды на своём dev-сервере.

Обновление применяет миграции до запуска новой версии. Автоматического
отката нет: откат приложения после миграции требует проверки совместимости
схемы. Перед будущими изменениями с риском потери данных нужна резервная копия.
