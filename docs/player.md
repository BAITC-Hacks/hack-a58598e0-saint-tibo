# Плеер записи

Задачи: #19, #20 и #95. Компонент находится в
`frontend/src/shared/ui/meeting-player/`; рабочая страница — `/player`
после входа. Она открывает защищённую запись пользователя через `media_url`
либо выбранный аудио/видеофайл через локальный `blob:` URL. Локальный файл
не загружается на сервер и не отправляется на обработку.
Поддержка контейнера и кодека зависит от браузера; неподдерживаемая запись
показывает ошибку и позволяет повторить попытку или выбрать другой файл.

## Подключение к странице совещания

```tsx
import { useRef } from "react";
import { MeetingPlayer } from "#/shared/ui/meeting-player";
import type { MeetingPlayerHandle } from "#/shared/ui/meeting-player";

const player = useRef<MeetingPlayerHandle>(null);

<MeetingPlayer
  ref={player}
  source={{
    id: recording.id,
    url: recording.media_url,
    title: recording.original_filename,
  }}
  onPositionChange={({ positionMs, durationMs, sourceId }) => {
    // Feed the transcript's active-segment selection for this recording.
  }}
/>;

// A transcript click seeks without changing the paused/playing state.
player.current?.seek(segment.start_ms);
player.current?.pause();
```

Все внешние таймкоды — целые миллисекунды. Время берётся из исходного медиа,
не из длительности последней реплики. Неизвестная длительность — `null`.
Перемотка до загрузки метаданных откладывается; отрицательное время
ограничивается нулём, время за концом — длительностью. Нечисловые значения
игнорируются. Смена `id` или URL останавливает и выгружает старое аудио.
Удаление компонента также останавливает воспроизведение.

Контролы: play/pause, ±10 секунд, диапазон позиции, скорость 0.5–2×,
громкость, состояние загрузки/буферизации/ошибки/завершения. Используются
общие токены и компоненты, строки RU/KK/EN. Кнопки доступны с клавиатуры,
диапазоны управляются стрелками. Глобальные горячие клавиши не перехватывают
редактор транскрипта или другие поля страницы.

Локальный плеер строит дорожку из самого выбранного аудио (до 32 MiB) и
показывает фрагменты из настоящих таймкодов загруженного транскрипта. Клик
по фрагменту перематывает то же медиа. Если декодирование недоступно или
файл больше лимита, дорожка не рисуется: синтетическую форму сигнала не
показываем. Большое серверное медиа не скачивается ради визуализации.

## Локальный транскрипт рядом с записью

После выбора WAV, который подавался в `scripts/benchmark-stt.py`, на
`/player` можно выбрать JSON результата. Страница проверяет форму сегментов и
SHA-256 этого WAV из `audio_sha256`, поэтому текст чужой записи не появится на
неверной временной шкале. Импорт ограничен 8 MiB для JSON и 256 MiB для
проверяемого аудио. Клик по реплике перематывает плеер; текущая реплика
подсвечивается, при ручной прокрутке автоследование отключается. JSON и аудио
остаются в браузере, не входят в Git и не передаются серверу. На странице
не запускается STT и не определяется говорящий; точность автоматического
текста требует ручной проверки.

Для локального прогона модели и получения приватного JSON см.
[`docs/stt-feasibility.md`](stt-feasibility.md). Исходный MP3 перед
benchmark преобразуется в PCM16/16 kHz/mono WAV; JSON содержит SHA-256 именно
этого WAV. В локальном каталоге `.data/stt/wav/` доступны обе подготовленные
демонстрационные записи, а JSON лежит в `.data/stt/results/`.

## Серверное медиа

По контракту #8/#9 URL — относительный `media_url` из записи, защищённый
same-origin cookie proxy и серверной проверкой владельца на каждом запросе,
включая HTTP Range/206. HTMLMediaElement не устанавливает произвольный
Authorization header. Плеер не создаёт вторую авторизацию, не хранит токены
и не скачивает весь файл через fetch ради установки заголовка. URL должен
относиться к той же временной шкале, что и реплики. Родитель снимает
компонент при смене сессии.

При использовании локальных файлов вызывающая страница владеет blob URL
и освобождает его при смене/удалении записи. Сохранение браузерной записи
через #9 и воспроизведение серверного `media_url` подключены на `/capture`.
На `/player` есть выбор готовых записей пользователя и локальный
предпросмотр. Ни один из экранов сам по себе не доказывает готовность
серверной транскрибации или платформенных подключений.

Демонстрационные материалы лежат локально в `shared/`, исключённой из Git.
Для проверки использовать два MP3 из этой папки; PDF — образцы протоколов,
а не транскрипт с таймкодами. Тестовые записи и личные пути не включаются
в сборку или deployment.

Поведение медиа проверяется по
[HTMLMediaElement](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement).
