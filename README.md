# Saint Tibo

Система автопротоколирования совещаний с фиксацией поручений для BAITC Hacks.
Целевой сценарий: запись → транскрипт с говорящими → поручения с ответственными
и сроками → саммари → протокол PDF/DOCX.

В ветке `dev` есть авторизация, совещания и участники, приватная загрузка и
воспроизведение записи, очередь обработки, локальные распознавание речи и
диаризация с таймкодами. Результат можно проверить и поправить вручную,
затем экспортировать подтверждённый протокол в PDF или DOCX. API-клиент
генерируется из OpenAPI. Интерфейс доступен на русском, казахском и английском.

| Возможность | Где смотреть | Что происходит |
| --- | --- | --- |
| Встречи и записи | [`/meetings`](https://dev-ivan.saint-tibo.win/meetings) | Создание встречи, добавление участников и MP3/WAV, запуск обработки |
| Плеер и протокол | [`/player`](https://dev-ivan.saint-tibo.win/player) | Приватное аудио, саммари, поручения, открытые вопросы, транскрипт, таймлайн голосов, фильтр реплик и «Слушать» одного говорящего. «Обработка и протокол встречи» раскрывает загрузку, обработку и ручную проверку |
| Карточка встречи | [`/meetings`](https://dev-ivan.saint-tibo.win/meetings) → встреча | Правка результата, назначение участников голосам, подтверждение и PDF/DOCX |
| Сегодня и предстоящее | [`/`](https://dev-ivan.saint-tibo.win/), [`/agenda`](https://dev-ivan.saint-tibo.win/agenda) | Короткий список и порядок сохранённых поручений |
| Задачи, календарь и аналитика | [`/tasks`](https://dev-ivan.saint-tibo.win/tasks), [`/calendar`](https://dev-ivan.saint-tibo.win/calendar), [`/analytics`](https://dev-ivan.saint-tibo.win/analytics) | Представления сохранённых поручений и их сроков; пустой результат возможен при отсутствии поручений |
| Напоминания | [`/notifications`](https://dev-ivan.saint-tibo.win/notifications) | Предстоящие и просроченные сроки, если для них есть подходящие поручения |
| Люди и брифинг | [`/people`](https://dev-ivan.saint-tibo.win/people), [`/briefing`](https://dev-ivan.saint-tibo.win/briefing) | Только явно добавленные участники и их доступные встречи; распознанное имя в тексте не создаёт человека автоматически |
| Оргсправочник | [`/ask`](https://dev-ivan.saint-tibo.win/ask) | Вопросы по именам, ролям участников и названиям доступных встреч через Honcho |
| Захват встречи | [`/capture`](https://dev-ivan.saint-tibo.win/capture) | Инструкция и запись текущей вкладки/системного звука для Google Meet, Teams и Zoom при разрешении браузера |

**Граница прототипа.** Автоматическое подключение бота к чужой встрече пока
не реализовано: запись запускает человек в браузере или загружает готовый файл.
Диаризация различает голоса, но присвоение имени голосу требует прослушать
образец и выбрать участника. Это не назначает его автоматически ответственным
по поручению: поле ответственного проверяется отдельно. Распознавание речи и
диаризация выполняются локально. Полная обработка с извлечением протокола
может выполняться локально и занимает время; отдельная кнопка быстрого
черновика появляется только при включённом и настроенном API-провайдере.
Тогда текст транскрипта уходит внешнему провайдеру. Honcho в текущей
конфигурации тоже может передавать внешнему провайдеру имена, роли, названия
встреч и вопрос. Эти временные режимы разрешены владельцем для прототипа,
но не отвечают требованию закрытого контура; перед внедрением их нужно
переключить на локальные модели. Эти OpenAI-совместимые API допускают
самостоятельный хостинг: пример с LM Studio и требования к схеме ответа —
в [извлечении](docs/api-extraction.md), настройки локальных моделей чата и
эмбеддингов — в [Honcho](docs/honcho-ask.md). Для контейнеров нужен доступный
им адрес модели; совместимость проверяется на синтетических данных. STT и
диаризация уже работают локально.

## Проверка для организаторов на тех же данных

Самый быстрый путь — [войти на dev-ivan](https://dev-ivan.saint-tibo.win/)
обычным тестовым пользователем (при отсутствии сессии вход происходит
автоматически) и открыть уже обработанные записи:

| Исходный файл | Готовая встреча | Что проверить |
| --- | --- | --- |
| [`input-audio/Совещание №1.mp3`](input-audio/Совещание%20№1.mp3) | [Совещание №1](https://dev-ivan.saint-tibo.win/meetings/666b27bb-fdde-4d4d-b7db-61836f2b5e77) | Саммари, говорящие, открытые вопросы; на проверке 23.09 — 76 реплик и 8 поручений |
| [`input-audio/Совещание №2.mp3`](input-audio/Совещание%20№2.mp3) | [Совещание №2](https://dev-ivan.saint-tibo.win/meetings/c8eb655d-7941-430d-a7d3-50229bdaa884) | Саммари и говорящие; на проверке 23.09 — 86 реплик и 5 поручений |

В [плеере](https://dev-ivan.saint-tibo.win/player) выберите одну из этих
записей: саммари, поручения, открытые вопросы и транскрипт находятся на одной
странице. Нажмите реплику для перехода к моменту в аудио, выберите говорящего
для фильтра, затем «Слушать» для воспроизведения только его фрагментов.
Раскройте «Обработка и протокол встречи», чтобы увидеть полный цикл. Старый
адрес `/workspace` перенаправляет на `/player`.
Задачи, календарь, аналитика, главная и предстоящее читают сохранённые
поручения этих же встреч; брифинг, люди и Honcho используют только явно
добавленных участников. Страница захвата показывает отдельный способ получить
новую запись из Meet/Teams/Zoom и не требует этих MP3.

Эти результаты принадлежат общей учётке `dev-user@saint-tibo.local`; если
открыта сессия другого пользователя, выйдите и снова откройте корень
dev-ivan. Пароль и режимы входа описаны в [руководстве](docs/browser-testing.md).
Не редактируйте общие готовые встречи во время оценки: для проверки записи,
ручной правки и экспорта создайте **свою копию** из тех же MP3. Репозиторий
содержит исходное аудио, но не базу dev-ivan, готовые транскрипты или
приватные ключи. В новом локальном/production окружении результат нужно
получить заново, подготовив модели по [инструкции](docs/transcription.md).
Готовые саммари — черновики: PDF/DOCX разблокируются после ручной проверки и
сохранения, поэтому в общих встречах эти кнопки могут быть неактивны.

Чтобы пройти сценарий **с нуля**, возьмите именно реальные файлы из репозитория:
[`input-audio/Совещание №1.mp3`](input-audio/Совещание%20№1.mp3) и
[`input-audio/Совещание №2.mp3`](input-audio/Совещание%20№2.mp3).
Скачайте нужный MP3 на свой компьютер; браузер не может выбрать файл из
папки GitHub автоматически.

1. Откройте [новую встречу](https://dev-ivan.saint-tibo.win/meetings/new),
   укажите название и дату. В карточке встречи добавьте известных участников,
   нажмите «Загрузить аудио» и выберите один из этих MP3.
2. В блоке обработки выберите «Транскрипт и говорящие» и запустите задачу.
   Дождитесь завершения: локальная обработка длинной записи занимает время.
   Появятся реплики с таймкодами и метками `speaker_00`, `speaker_01` и т. д.
3. Исходный протокол после транскрибации может быть пустым. На dev-ivan в
   **нетронутой** ревизии нажмите «Сформировать черновик» **до сохранения
   любых ручных правок**: сейчас эта кнопка использует временный API.
   Альтернатива — перед запуском задачи выбрать режим «Транскрипт, говорящие
   и черновик протокола» для локального извлечения (оно может занять около
   15 минут или дольше). Черновик не считается проверенным протоколом.
4. В блоке «Говорящие» прослушайте ссылку на фрагмент, выберите имя участника
   у нужной метки и сохраните правку. Это подпишет голос в протоколе и
   таймлайне. В [плеере](https://dev-ivan.saint-tibo.win/player) выберите
   серверную запись, нажмите на метку голоса для фильтра реплик или «Слушать»
   для последовательного воспроизведения его фрагментов; «Все голоса»
   вернёт обычное воспроизведение. Проверьте темы, решения, открытые вопросы,
   каждого ответственного и срок; исправьте неточности, отметьте протокол
   проверенным и сохраните. После этого станут доступны «Скачать PDF» и
   «Скачать DOCX».
5. В [задачах](https://dev-ivan.saint-tibo.win/tasks) найдите поручения своей
   встречи, а в [календаре](https://dev-ivan.saint-tibo.win/calendar) — даты
   их исполнения. [Аналитика](https://dev-ivan.saint-tibo.win/analytics)
   показывает счётчики по тем же сохранённым поручениям. [Напоминания](https://dev-ivan.saint-tibo.win/notifications)
   появятся только при подходящем сроке поручения; пустой экран
   сам по себе не означает ошибку.
6. В [брифинге](https://dev-ivan.saint-tibo.win/briefing) выберите **явно
   добавленного** участника
   и нажмите «Собрать брифинг». Содержимое зависит от сохранённых выводов и
   поручений в доступных вам встречах. В [оргсправочнике](https://dev-ivan.saint-tibo.win/ask)
   задайте вопрос об участнике или его роли; ответы используют записи
   участников, а не полный транскрипт. При выключенном Honcho появится
   сообщение о недоступности.

Проверяйте сценарий под одним и тем же аккаунтом: доступ к записи,
протоколу и справочнику ограничен владельцем встречи. Кнопка быстрого
черновика доступна только пока результат с транскриптом не редактировали и
не сохраняли; при недоступном API она сообщит об ошибке, а исходный
транскрипт останется доступным.
Контракт загрузки — в [документации](docs/recording-storage.md), очередь —
в [processing-jobs.md](docs/processing-jobs.md), локальный STT —
в [transcription.md](docs/transcription.md).

## Запуск

Основной рабочий цикл — ручная проверка на личном dev-сервере, без CI/CD.
[Инструкция](docs/dev-server.md): для сервера Ивана
`sh scripts/dev-deploy.sh saint-dev-ivan` (каждый использует свой сервер).
Для обработки заранее подготовьте локальную модель по
[инструкции STT](docs/transcription.md). Наличие HTTPS и входа само по себе
не означает, что нужные модели установлены в новом окружении.

Для проверки в браузере просто откройте свой dev-домен:
[Данил](https://dev-danil.saint-tibo.win),
[Иван](https://dev-ivan.saint-tibo.win),
[Артём](https://dev-artem.saint-tibo.win).
Вход обычным тестовым пользователем автоматический. Администратор:
`/dev-login?role=admin`; ручной вход: `/login`.
Dev-аккаунты, переключение ролей и инструкции для browser-use —
в [коротком руководстве](docs/browser-testing.md).

Для полного локального запуска нужны Git, Bun **1.4.2**, uv **0.12.13+**, Docker с Compose.
uv установит Python 3.13 по `backend/.python-version`.
При запуске backend вне Docker для загрузки аудио нужны `ffmpeg` и `ffprobe` в PATH;
Docker-образ уже содержит их. Записи сохраняются в приватном persistent volume.

```sh
git clone https://github.com/BAITC-Hacks/hack-a58598e0-saint-tibo.git
cd hack-a58598e0-saint-tibo
git switch dev
bun run setup
bun run dev
```

Открыть [приложение](http://localhost:3000), зарегистрироваться и войти.
[Swagger](http://localhost:8000/docs), readiness: `http://localhost:8000/health/ready`.
Регистрация создаёт обычного пользователя; права администратора выдаются отдельно.

`setup` устанавливает зависимости из lock-файлов, создаёт корневой `.env`
со случайным секретом, запускает PostgreSQL и применяет миграции.
Повторный запуск сохраняет секрет и данные. `Ctrl+C` останавливает приложения;
`bun run infra:stop` останавливает базу без удаления данных.

Для локальных демонстрационных аккаунтов: `bun run seed`.
Они создаются только этой командой: `admin@saint-tibo.local` и
`user@saint-tibo.local`, пароль `saint-tibo-dev` (переопределяется `SEED_PASSWORD`).
Этот локальный seed не предназначен для серверов. На трёх dev-серверах
deployment запускает отдельный ограниченный `seed:dev`; в production
тестовые аккаунты не создаются. Рабочие аккаунты создаются через регистрацию.

## Команды

| Команда из корня | Назначение |
| --- | --- |
| `bun run setup` | Зависимости, окружение, база, миграции |
| `bun run install:all` | Только зависимости из lock-файлов |
| `bun run dev` | База, миграции, API и frontend с перезагрузкой |
| `bun run build` | Production frontend и Python-пакет |
| `bun run verify` | Типы, существующие проверки, сборка |
| `bun run test:integration` | Авторизация и миграции в одноразовой БД Docker |
| `bun run api:generate` | OpenAPI → TypeScript SDK и Query helpers |
| `bun run migrate` | Drizzle для `auth`, Alembic для `app` |
| `bun run admin:grant <email>` | Выдать роль администратора локальному аккаунту |
| `bun run demo` / `demo:stop` | Собрать и запустить / остановить весь стек в Docker |

`demo` требует `.env`, подготовленный `setup`. Порты Compose привязаны
к loopback. Ручной серверный запуск добавляет Caddy с HTTPS и отдельное
окружение. Production: https://saint-tibo.win; адреса личных dev-серверов
и команды — в [инструкции](docs/dev-server.md).

## Структура

| Каталог | Ответственность |
| --- | --- |
| `frontend/` | React 19, TanStack Start, TypeScript 7, Tailwind, shadcn/Base UI |
| `backend/src/saint_tibo/` | FastAPI, авторизация, ошибки, health, предметные модули |
| `backend/migrations/` | SQLAlchemy/Alembic, прикладная схема `app` |
| `frontend/drizzle/auth/` | Better Auth/Drizzle, схема `auth` |
| `contracts/openapi.json` | Проверяемый снимок API |
| `tools/api-client/` | Изолированный генератор TypeScript-клиента |
| `input-audio/` | Два исходных MP3 кейса, добавленные владельцем для проверки |
| `build/stack-pin.json` | Стек и архитектурные решения |

Настройки — в корневом `.env`; образец — `.env.example`.
Для параллельных копий задавайте уникальные `COMPOSE_PROJECT_NAME`,
`POSTGRES_PORT`, `FRONTEND_PORT`, `BACKEND_PORT` и имя базы.
